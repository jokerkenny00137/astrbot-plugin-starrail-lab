# astrbot_plugin_starrail_lab

一个 AstrBot 插件：输入玩家 UID，查出他在《崩坏：星穹铁道》里公开的角色面板和遗器。

> 本项目与米哈游 / HoYoverse 无关，仅用于个人学习和娱乐。

---

## 功能

- `/面板 <UID>` —— 先列出该玩家展示柜里有**哪些角色**，避免一次刷屏
- `/面板 <UID> 角色名` —— 只看某个角色的完整面板
- 面板包含：等级、命座、光锥、攻击 / 生命 / 防御 / 速度、暴击率、暴击伤害、属性伤害加成
- 列出每件遗器的主词条与全部副词条
- `/绑定 <UID>` —— 把自己的 QQ 和游戏账号绑定，之后直接发 `/面板` 即可
- `/刷新 [UID]` —— 后台刷新某个玩家的数据与角色卡，不填 UID 就刷新你最近查看 / 绑定的玩家
- **查询结果会自动进入 AI 上下文**：查完面板继续聊天时，AI 能看懂这份数据并据此给建议
- **可编辑的练度分析说明词**：内置一套「定位 → 面板体检 → 遗器诊断 → 光锥命座 → 提升优先级」的分析框架，可在控制面板自由修改，让 AI 的练度分析更有逻辑
- 支持定时自动更新已绑定玩家的面板数据（可在插件配置页 / 控制面板开启）
- **查询走本地优先**：刷新过的玩家数据存在本地数据库，日常查询直接读本地，不再受公共接口排队影响；只有发 `/刷新` / 在控制面板刷新 / 定时任务才联网
- **未绑定玩家的缓存会自动过期**：只查过一次的玩家，面板与角色卡默认保留 3 天后自动清理；已绑定玩家永久保留（可在设置里调整天数，填 0 关闭清理）
- **自带 WebUI 控制面板**：增删绑定、浏览本地存档的玩家数据、预览角色卡、调整设置、环境自检
- **单个角色详情会渲染成图片角色卡**：深色卡片，含头像、光锥、12 项属性、遗器套装与六件遗器词条；渲染不可用时自动回退成文字
- **角色卡本地缓存**：刷新后可在后台预渲染成 PNG，查询时直接发本地图，绕开渲染失败；同一张图不会重复渲染
- **本地角色机制卡**：把角色定位、核心机制、关键属性写成 `guides/角色名.md`，AI 回答机制问题前会主动查询，查不到就直说没有资料，减少凭记忆编造
- **高权重属性金色标注**：按角色属性权重表（暴击率 / 爆伤 / 速度等）把有效属性标成金色；遗器的主词条与副词条中的关键属性同样会金色标注
- **遗器加权评分**：每件遗器满分 10 分（如 `7.6 / 10`），六件合计满分 60 分，卡片上会给出遗器总分；按该角色副词条权重与强化次数折算，权重表没收录的角色不显示评分
- **星级配色**：头像框与光锥底图按星级着色——五星金、四星淡紫、三星灰
- **遗器图标**：按遗器套装 ID 从公共素材库拉取，散套会自动合并显示为「散件」
- 解析库遇到尚未收录的新角色（如 `avatarId 1511`）时，会自动跳过该角色并保留其余角色，不再整次查询失败

## 安装

### 前置要求

- AstrBot `>= 4.5.0`
- **Python 3.11 或更高版本**（依赖库 `starrail_damage_cal` 的硬性要求，低于 3.11 装不上）

### 方式一：插件市场

在 AstrBot 的 WebUI「插件」页面搜索 `astrbot_plugin_starrail_lab` 安装。

### 方式二：手动安装

1. 下载本仓库的 ZIP 并解压
2. 把整个文件夹放到 AstrBot 的 `data/plugins/` 目录下
3. 重启 AstrBot，或在 WebUI 插件页点击刷新
4. 确认日志里出现 `[星铁面板] 已加载`

依赖会在插件加载时自动安装。如果自动安装失败，可以手动执行：

```bash
pip install -r requirements.txt
```

## 使用

### 直接查（不用绑定也可以）

先看这个玩家有哪些角色：

```
/面板 100000000
```

```
【某玩家】UID 100000000
展示柜共 8 个角色：

  1. 某角色  Lv80  雷  某光锥
  2. 某角色  Lv80  风  某光锥
  ...

想看哪个角色的详细面板，发：
  /面板 100000000 角色名
  /面板 100000000 序号      （例如 /面板 100000000 1）
  /面板 100000000 全部      （一次看完整份）
```

然后挑一个看详情：

```
/面板 100000000 1
/面板 100000000 某角色
/面板 100000000 全部
```

> 只查**单个角色**时，默认会发一张图片角色卡（`auto` 模式）。如果当前环境渲染不了图片，会自动改发原来的文字面板，不会报错。
>
> 查询默认使用**本地存档**：玩家数据一旦刷新过，之后的查询不会再联网，也不会因为公共接口排队而失败。想看最新数据就发一次 `/刷新`。

刷新（联网拉取最新数据并更新本地存档）用 `/刷新`，它在后台跑，不占聊天：

```
/刷新 100000000     # 刷新指定玩家
/刷新               # 刷新你最近查看的玩家；没查过则刷新绑定账号
```

> `/刷新` 是异步的，回复「已开始后台刷新」后就去干活了，过一会儿再发 `/面板` 就能看到新数据。
> 旧写法 `/面板 100000000 刷新` 仍然可用（等价于 `/刷新`），但已经不再出现在提示文案里。

刷新失败时会自动回退到本地旧数据，并在消息里提示，不会把已有存档清掉。

指令别名：`/星铁面板`、`/崩铁面板`、`/查面板`、`/角色面板`、`/星穹面板`、`/查uid`
`/刷新` 的别名：`/刷新面板`、`/更新面板`

> 如果已经绑定，`/面板 1` 里的短数字会被当作角色序号，而不是 UID。

### 推荐：绑定一次，之后免输 UID

```
/绑定 100000000     # 绑定（一个 QQ 只保留一个 UID，重复绑定就是换绑）
/选择查询           # 列出展示柜里的角色
/选择查询 1         # 看第 1 个角色的详细面板
/选择查询 希儿      # 按角色名看
/选择查询 全部      # 一次看完整份
/我的绑定           # 查看当前绑定的 UID
/解绑               # 解除绑定
```

`/选择查询` 的别名：`/选角色`、`/看角色`、`/查询角色`

> `/选择查询` 默认接着**你在当前会话里最近查过的那个人**（按「会话 + 发送者」记录，群里其他人查询不会影响你）。所以先用 `/面板 别人的UID` 查了别人的展示柜，再发 `/选择查询 角色名` 看的就是那个人的角色；想切回自己，发一次 `/面板 自己的UID` 即可。

> 一个 QQ 号只能绑定一个 UID。重复绑定会自动覆盖旧的，相当于换绑。

管理员可以发 `/绑定列表` 查看所有绑定记录，`/刷新全部面板` 后台刷新所有已绑定玩家，也可以在 WebUI 控制面板里增删、刷新。

### 让 AI 看懂查询结果

这是本插件比较特别的一点。

查询完面板后，**在同一个群/私聊里继续聊天**，插件会把这份面板数据作为临时用户内容附加到本轮请求（`extra_user_content_parts` + `mark_as_temp()`，不改写 `system_prompt`，不影响 prompt 缓存），所以你可以直接问：

> 我这只希儿的暴击率够不够？
> 遗器套装搭配有问题吗？
> 光锥要不要换？

AI 会基于真实数据回答，而不是凭记忆编造。

同时会附上一段**练度分析说明词**，要求 AI 按「结论 → 面板体检 → 遗器诊断 → 光锥命座 → 提升优先级 → 数据不足时说明缺口」的结构回答。只在问题涉及面板/练度/遗器/光锥等关键词时才附加，闲聊不会套模板。这段说明词可以在控制面板「设置」页随时修改，也可以清空来关闭。

有效期默认 30 分钟（可在插件配置里改），过期后自动失效，避免拿旧数据当现状。

### 减少「机制瞎编」：本地角色机制卡

面板数据只能让 AI 知道「这个角色现在是什么属性」，不能让它知道「这个角色怎么玩」。所以问技能机制时，模型仍然可能凭记忆编。

为此插件支持一套**本地机制卡**：在插件数据目录的 `guides/` 下放 `角色名.md`，AI 回答机制问题前会先查资料。

```
<AstrBot data>/plugin_data/astrbot_plugin_starrail_lab/guides/
├── 黄泉.md
└── 流萤.md
```

文件首行必须是标题，名称匹配靠它：

```markdown
# 黄泉（虚数 · 虚无 · 主C）

## 定位
靠「集真赤」层数驱动终结技的虚数主C，不依赖常规能量条。

## 核心机制
- 天赋：队友施放技能时为她叠层
...

## 关键属性
暴击率、暴击伤害、攻击力、虚数属性伤害加成

## 常见误区
不需要击破特攻
```

几条要求：

- 一个角色一个文件，文件名用角色名；
- 单个文件建议不超过 1200 字（超出会被截断，可在配置里调整上限）；
- 只写确定的内容，不确定的整条删掉；
- 插件自带 5 个示例模板，可以照抄改写，也可以直接覆盖。

相关指令：

| 指令 | 作用 |
|---|---|
| `/角色资料` | 查看已收录哪些角色 |
| `/角色资料 <角色名>` | 预览某个角色的机制卡 |
| `/重载资料` | 改完 md 文件后重新读取，不用重启（管理员） |

> 工具名是 `query_character_guide`。如果所用模型不支持工具调用（部分中转模型会禁用），AI 不会主动查资料，此时只能依赖提示词约束，效果会打折扣。
>
> 开关在插件配置的「启用本地角色机制卡」。

### 为什么查不到数据

插件读取的是**玩家公开的角色展示柜**，需要满足：

1. UID 输入正确
2. 该玩家在游戏里开启了「角色展示柜」，并且把角色放进去了

如果对方没开，接口不会返回角色数据，插件会提示查不到。

## 数据来源与引用说明

本项目本身不包含任何游戏数值，数据链路如下：

### 1. 计算与数据解析：starrail_damage_cal

- 包名：`starrail_damage_cal`（PyPI）
- 本项目使用版本：`4.6.0`
- 许可证：**MIT**
- 作者：qwerdvd、ilnli
- 地址：https://pypi.org/project/starrail_damage_cal/

该库负责：

- 把 Mihomo / 米游社的角色数据转换为统一模型
- 从遗器主副词条 ID 反算实际数值
- 提供角色基础属性成长表、光锥成长表、词条倍率表等本地资源

本项目只是**调用**它，没有修改其源码。所有属性计算公式（基础值 × (1 + 百分比) + 固定值）实际由该库提供的数据表驱动。

### 2. 数据接口：Mihomo API

- 地址：`https://api.mihomo.me`
- 用途：按 UID 拉取玩家角色展示柜（角色、光锥、遗器词条）

Mihomo 是第三方开源项目，其数据原始来源为米游社 / HoYoLAB 的角色展示接口。本项目不对该服务的可用性、准确性做任何保证。

该接口为公共实例，高峰期可能排队超时，插件对此做了重试和友好提示。

### 3. 游戏内容版权

《崩坏：星穹铁道》及其角色、光锥、遗器、技能名称、数值等内容的著作权归 **米哈游 / HoYoverse** 所有。

本项目：

- 不包含任何游戏素材文件（图片、模型、音频）
- 不提供游戏本体或任何破解内容
- 仅对公开的玩家展示数据进行读取和格式化展示
- 与米哈游 / HoYoverse 无任何关联，未获其授权或认可

## 隐私说明

- 本插件只读取**玩家主动公开**的展示柜数据，不涉及账号登录、密码、Cookie
- 不使用任何私人接口，不绕过任何访问限制
- 刷新时拉到的原始数据缓存在 **AstrBot 的 `data/plugin_data/astrbot_plugin_starrail_lab/cache/` 目录**（10 分钟内复用），完整面板存档在 `starrail.db`，角色卡在 `cards/`
- 这些数据**不会**上传到任何服务器，也不会提交到本仓库（已在 `.gitignore` 中排除）
- 未绑定玩家的存档与角色卡默认 3 天后自动清理（每 6 小时检查一次），绑定玩家永久保留
- 如需彻底清除，删除上述 `cache`、`cards` 目录和 `starrail.db` 即可

## 已知限制

- **只查展示柜**：玩家没公开的角色查不到，这是游戏机制决定的，不是插件问题
- **不含光锥技能效果**：面板已包含光锥基础属性和遗器词条，但不含光锥的被动技能（如「装备者暴击率提高 8%」），因此与游戏内面板可能存在少量差异
- **公共接口不稳定**：`api.mihomo.me` 排队时查询可能超时，稍后重试即可

## 关于配队伤害计算（实验性，未接入指令）

仓库里的 `team_damage.py` 是早期写的配队伤害计算逻辑，可用 `calculate_team_damage()` 在本地脚本里直接调用。

但它依赖的 `starrail_damage_cal` 只实现了 **50 个角色的伤害逻辑，最新只到 2.2 版本的「知更鸟」**。之后的新角色会抛 `UnsupportedAvatarError`。

因此这部分目前**没有**接入 AstrBot 指令，仅作为后续扩展的骨架保留。

## 控制面板

AstrBot 的 WebUI → 插件 → 本插件详情页 → **打开视图「星穹铁道面板查询」**。

界面是银河蓝底 + 磨砂玻璃风格，左侧为导航栏，顶部一条 HUD 显示绑定数、存档数和最近更新时间。右上角搜索框是全局的：可以过滤绑定表、UID 横条、角色横条、设置项和自检项，没命中会给出提示。手机端导航默认收起，点右上角「菜单」拉出带彩色图标的抽屉。

面板里有四个标签页：

- **绑定管理**：查看 / 新增 / 删除绑定，单独或批量刷新
- **玩家数据**：顶部横向 UID 选择条（点一下直接加载），下面是横向角色选择条；角色卡按屏幕高度缩放，一屏放得下，点图片或「放大查看」会在蒙版里打开可缩放大图（滚轮 / 按钮缩放，Esc 关闭）。桌面端文字面板在右侧，手机端排在角色卡下方。图片拿不到时自动改用 HTML 渲染，再失败才显示文字
- **设置**：按「输出与渲染 / 角色卡与缓存 / 数据更新 / AI 上下文」分成四个小板块，改完保存立即生效（自动更新间隔会重启定时任务）
- **自检**：一键检查 Web 接口、解析库、遗器评分表、`html_render`、模板、图片下载组件、角色卡冷却状态，并显示数据目录、渲染日志路径、最近一次刷新结果

面板通过 AstrBot 官方的 Plugin View bridge 调用后端接口，不直接发 HTTP 请求，符合沙箱安全要求。

对应的后端接口（`Context.register_web_api` 注册）：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/astrbot_plugin_starrail_lab/bindings` | 列出绑定关系 |
| POST | `/astrbot_plugin_starrail_lab/bindings/add` | 新增绑定 |

## 插件配置

在 AstrBot 的 WebUI「插件」页面点「配置」，或直接在控制面板的「设置」页修改（保存后立即生效）：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 角色详情输出方式 | `auto` | `auto` 能渲染就发图片、失败回退文字；`image` 同上但失败会记日志；`text` 只发文字 |
| 角色卡渲染超时（秒） | `30` | 远端渲染服务较慢时调大，范围 5~120；超时后自动用 20 秒重试一次，仍失败才回退文字 |
| 角色卡失败后冷却（分钟） | `5` | 渲染失败后在冷却期内直接发文字，避免每次都卡到超时；冷却结束自动恢复出图，填 0 表示每次都尝试 |
| 自动更新间隔（分钟） | `0`（关闭） | 开启后定期刷新所有已绑定玩家的面板并存入数据库。建议 30 分钟以上，别给公共接口太大压力 |
| 未绑定玩家缓存保留（天） | `3` | 只清理未绑定玩家的面板存档与角色卡，绑定玩家永久保留；填 `0` 关闭清理 |
| 面板数据注入 AI 上下文的有效期（分钟） | `30` | 查询后多久之内继续聊天，AI 还能看到这份数据 |
| 刷新后自动预渲染角色卡 | 开启 | 刷新后在后台把角色卡存成本地 PNG，查询时直接发本地图 |
| 角色卡图片内嵌 | 开启 | 头像/光锥/遗器图转 base64 一起发渲染端，图更稳但请求体大；经常超时可关闭 |
| 自动切换渲染端点 | 开启 | 内置两个官方渲染端点 + 官方列表接口，逐个短超时尝试，失败快速切换 |
| 自定义渲染端点 | 空 | 可填自建文转图服务地址，如 `http://127.0.0.1:8999/text2img`；留空用官方端点 |
| 练度分析说明词 | 内置分析框架 | 查完面板后随数据交给 AI，决定怎么分析练度；留空则不注入 |

数据存放在 AstrBot 的 `data/plugin_data/astrbot_plugin_starrail_lab/`：

```
starrail.db        # 绑定关系 + 最近的查询记录 + 面板存档
cache/             # 接口原始数据缓存（刷新时写入）
cards/<UID>/       # 角色卡本地图片与 HTML
card_render.log    # 角色卡渲染日志（排查不出图 / 超时）
```

### 排查角色卡问题

1. 先看控制面板「自检」页：`html_render`、模板、图片下载组件、冷却状态一目了然
2. 点「测试渲染」：会用插件自己的端点轮询测一次极简页面，并显示成功的是哪个端点
3. 官方端点 `t2i.soulter.top` 偶尔会返回 `503 no available server`，插件会自动切到 `t2i.rcfortress.site`；如果两个都不可用，可以自建：

   ```bash
   docker run -itd -p 8999:8999 soulter/astrbot-t2i-service:latest
   ```

   然后在控制面板把「自定义渲染端点」填成 `http://<你的地址>:8999/text2img`
4. 角色卡的渲染 / 缓存 / 失败原因会追加写入 `card_render.log`
5. AstrBot 主日志在 `data/logs/`（容器里是 `/AstrBot/data/logs/`），也可用 `docker logs <容器名>` 查看
6. 日志级别调到 `DEBUG` 才能看到渲染耗时等细节；常规失败会以 WARNING 出现在主日志里
